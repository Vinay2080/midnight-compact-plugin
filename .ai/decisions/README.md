# Architectural Decision Records (ADRs)

This directory contains the formal Architectural Decision Records for the Midnight Compact IntelliJ Plugin. Every architectural decision is recorded with:
1. **Context & Problem Statement**: The exact language constraint or IDE behavior being addressed.
2. **Authoritative References**: Ground truth citations from the official upstream Midnight compiler (`compact/compiler/` or `references/`) and reference JetBrains plugins (`intellij-rust`, `intellij-scala`, `intellij-elixir`, `Rplugin`).
3. **Decision & Architecture**: The structural solution adopted.
4. **Scalability & Anti-Hardcoding Evaluation**: Rigorous analysis demonstrating why the approach is scalable and universal rather than brittle or hardcoded.
5. **Feature Implementation Map**: Exact file paths, classes, and test suites implementing the decision.
6. **Consequences & Future Maintenance**: Guidelines for updating or refactoring the design in future phases.

## Mandatory Criteria for Architectural Decisions

Whenever proposing or refining a feature:
1. **Never Hardcode Assumptions**: Do not inject arbitrary defaults (e.g. `: Void` after `:` or `Bytes[]` for byte arrays) that mask developer intent or violate the language specification.
2. **Consult Upstream First**: Check `compact/compiler/parser.ss`, `lexer.ss`, and `langs.ss` for canonical language grammar and semantics.
3. **Compare with Mature Reference Plugins**: When IDE API behavior is nuanced (e.g. Enter handlers, code style, refactoring), consult `intellij-rust`, `intellij-scala`, or `intellij-elixir` in the workspace to follow JetBrains platform best practices.
4. **Document Immediately**: Add or update an ADR in this directory and log the reference in `CHANGELOG.md`.
